# S10 — Zero-credential Docker deployment (spec + outcome)

Slice S10 of the Recorded-Mode Engine plan. Decision record: `docs/adr/0007-recorded-container-deployment.md`. Operational doc: `docs/plans/waypoint/DEPLOYMENT.md`. Status: **DONE 2026-08-26** — gate 136 passed / 0 failed / 4 deselected (3 live + 1 eval), unchanged by this slice.

S9 made the recording replayable; S10 makes it deployable. Orkestr's deployment finding is inherited wholesale (quoted in ADR 0007): the live Atlas CLI **cannot** deploy (browser OAuth + OS keyring), so the deployed app serves the recording and says so — and the stack runs correctly with **zero credentials**.

## Deliverables (what changed)

- `docs/adr/0007-recorded-container-deployment.md` — the decision record: credential-free backend image, explicit recorded opt-in, armed-but-toothless `WAYPOINT_LIVE_BOOKING`, single worker + SQLite, prewarm boot-seeding, CORS override, honesty register on the wire.
- `backend/Dockerfile` + `backend/.dockerignore` — `python:3.11-slim` (client.py's floor); installs `requirements.txt`; copies `app/` + `scripts/` + `data/recorded/` ONLY — no tests, no `.env`, no venv; **no `atlas-flight` CLI, no `uv`, no keyring packages** (the recorded client never spawns a subprocess). Ships an empty `waypoint.db` as the no-volume fallback; `CMD` runs ONE uvicorn worker (`--workers 1` — one SQLite file; `asyncio.to_thread` DB access is the concurrency model).
- `frontend/Dockerfile` + `frontend/.dockerignore` — `node:20-alpine`, three stages (`npm ci` → `next build` → standalone runner). `NEXT_PUBLIC_API_URL` is a build-arg (default `http://localhost:8000` — baked into the client bundle; the viewer's browser calls the backend directly). Next 15.5 supports `output: "standalone"` natively: `next.config.mjs` gates it behind `NEXT_STANDALONE=1` (set only in the container build) so local `next dev`/`next build` behavior is untouched. Runner serves on 3000 (`HOSTNAME=0.0.0.0`, `PORT=3000`).
- `docker-compose.yml` (repo root) — three services:
  - `backend` — env `WAYPOINT_ATLAS_MODE=recorded` (explicit opt-in; the switch defaults live) and `WAYPOINT_LIVE_BOOKING=1` (ARMED and safe — documented inline: the gates decide WHETHER writes execute, the rail decides WHERE envelopes come from; the recorded client has no transport to a provider and fails closed with `NO_RECORDING`, so arming it can order nothing). NO `DASHSCOPE_API_KEY`, NO `SANDBOX_*` keys. Named volume `waypoint-db` mounted as a directory at `/app/db` with `WAYPOINT_DATABASE_URL` parking the SQLite file there (a named volume mounted on a FILE path initializes as a directory — discovered live during the S10 smoke test — so the file mount was rejected); healthcheck on `/api/health`.
  - `frontend` — build-arg `NEXT_PUBLIC_API_URL`, port 3000.
  - `prewarm` — boot seeding via the EXISTING `scripts/prewarm.py` pattern: one-shot container (same image, no rebuild) that waits for the backend healthcheck, seeds a desk, runs its recorded cycle to settle, and verifies the SSE replay buffer — a fresh `docker compose up` lands on a ready desk whose cold open replays from event 0. One knob makes that true: `WAYPOINT_ESCALATION_WAIT=5` — inside a container nobody makes the one human escalation click, and the 300s demo default would stretch boot seeding past five minutes (found live in the smoke test: the first run parked on the `escalate` event); the short wait expires the escalation on the loop's fail-closed bounded-wait path and the cycle gives up gracefully.
- `backend/app/main.py` — CORS `allow_origins` env-overridable via `WAYPOINT_CORS_ORIGIN` (comma-separated, trimmed, blanks dropped); unset/empty keeps the EXACT pre-S10 list `["http://localhost:3000", "http://localhost:3001"]`.
- `backend/app/db/database.py` — `DATABASE_URL` env-overridable via `WAYPOINT_DATABASE_URL` (unset keeps the exact pre-S10 `sqlite:///./waypoint.db`) — the container volume mount described above.
- `backend/app/api/routes.py` — `AGENT` escalation wait env-overridable via `WAYPOINT_ESCALATION_WAIT` (unset/unparsable/negative keeps the exact 300s demo default) — the boot-seeding knob described above.
- `docs/plans/waypoint/DEPLOYMENT.md` — zero-credential table (what runs where, what is absent), composite-recording disclosure, post-deploy smoke checklist (seed → SSE replay → honest recorded label → zero outbound provider calls), and `docker compose up` instructions for any VPS.

## Constraints honored

- ZERO edits to `backend/app/atlas/*` and `backend/app/agent/loop.py` — deployment rides S9's seam (`build_atlas()` in routes.py) untouched.
- Live behavior unchanged outside containers: `WAYPOINT_ATLAS_MODE` unset → live; `NEXT_STANDALONE` unset → default Next output; `WAYPOINT_CORS_ORIGIN` / `WAYPOINT_DATABASE_URL` / `WAYPOINT_ESCALATION_WAIT` unset → the exact pre-S10 values.
- No new backend dependencies; the image installs exactly `requirements.txt`.

## Verification

- Gate: `cd backend; .venv\Scripts\python -m pytest` → **165 passed, 4 deselected** (3 live + 1 eval) — S10's own gate run was 136/4, identical to the S9 baseline; the extra 29 are the concurrent S12 provenance tests landed mid-session. S10 adds no production-code tests because it adds no production logic beyond the env overrides (covered by the default-preservation checks below).
- CORS default preserved: with `WAYPOINT_CORS_ORIGIN` unset, `_cors_origins()` returns the exact pre-S10 list (asserted by reading the module under the empty environment; the middleware construction is module-level and exercised by every existing route test).
- Docker evidence (this machine, Docker Desktop 29.6.2): `docker compose build` — both images built (`waypoint-backend` ~294MB, `waypoint-frontend` ~300MB). `docker compose up -d` — backend healthy; `prewarm` seeded `desk-4f1fc8dc`, ran its recorded cycle to settle (`status=escalated`, pnl 841.00, 0 policy breaches, auditor `deterministic-fallback`) and verified the SSE replay buffer (21 buffered events, terminal result present). A SECOND seeded desk replayed byte-identically (same status/pnl/breaches — the per-cycle cursor rewind). The stream's `meta` carried `"mode": "recorded ticketing (replay)"` + the manifest's composite disclosure + the four provenance rails (Atlas=recorded, Qwen=fallback, Priors=curated, Ledger=real). Zero outbound provider calls: `atlas-flight` and `uv` absent from the container, `keyring` not importable, `docker compose config` contains no `DASHSCOPE`/`SANDBOX_*` entries, backend logs show only localhost/compose-network requests. Frontend root served HTTP 200. One smoke-test caveat: host port 8000 was held by a concurrent agent's local uvicorn, so the smoke run remapped the backend host port to 8010 via a scratch override file (`.qoder/s10-smoke-override.yml`, deleted after); the delivered `docker-compose.yml` publishes 8000 and was otherwise run verbatim.
