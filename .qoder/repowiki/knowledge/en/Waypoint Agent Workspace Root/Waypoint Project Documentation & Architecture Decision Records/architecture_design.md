The module is a flat documentation tree organized by purpose rather than code layers. `plans/waypoint/` holds the gated project plan anchored by `00-status.md`, which enumerates gate approvals (Product, Architecture, Program Design, Slice plan), slice sequencing S1–S8, locked decisions, judging rubric, and build workflow constraints; it cross-links to sibling files via numeric references (`[[0002]]`, `[[0003]]`) and to ADRs under `adr/`. Sub-files break down product vision (`01-product.md`), system design (`02-architecture.md`), program design (`03-program-design.md`), and slice deliverables (`04-slices.md`), plus HTML mockups under `mockups/` and per-slice handoff/readme notes. `adr/` stores immutable Architecture Decision Records in a fixed Context → Decision → Consequences template, each prefixed `NNNN-` and stamped with an Accepted date (with amendments when mechanisms change). `external/atlas-integration.md` isolates durable operational context about the Atlas Flight Booking Skill CLI surface, OAuth + OS keyring auth, environment switching, UAT module selection, and ticketing activation status — explicitly containing no secrets. Documents reference each other via relative links and form the single source of truth read before any implementation session.
