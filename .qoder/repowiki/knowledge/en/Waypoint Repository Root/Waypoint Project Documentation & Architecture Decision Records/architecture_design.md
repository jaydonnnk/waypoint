The module is a flat documentation tree organized by purpose rather than code layers. `plans/waypoint/` holds the gated project plan with an entry-point status file (`00-status.md`) that enumerates gate approvals, slice sequencing (S1–S8), locked decisions, judging rubric, and build workflow constraints; it cross-links to sibling files via numeric references (`[[0002]]`, `[[0003]]`). Subdirectories under `plans/waypoint/` break down product vision (`01-product.md`), system design (`02-architecture.md`), program design (`03-program-design.md`), and slice deliverables (`04-slices.md`), plus HTML mockups of the three demo screens and handoff notes per slice. `adr/` stores immutable Architecture Decision Records in a fixed Context → Decision → Consequences template, each prefixed `NNNN-` and stamped with an Accepted date. `external/atlas-integration.md` isolates durable operational context about the Atlas Flight Booking Skill API surface, OAuth + OS keyring auth, environment switching, and ticketing activation status — explicitly containing no secrets. Documents reference each other via relative links and form the single source of truth read before any implementation session.
